# Crypto Autobot

Единый бот для круглосуточной торговли криптовалютными USD-M Futures:

- получает закрытые свечи Binance Production для Binance-профилей и бары терминала брокера для MT5-профилей;
- объединяет short-возврат импульса и cost-aware order-flow модель на закрытых 15m свечах;
- работает в режимах Paper, Binance Demo/Live и MT5 Demo/Live;
- рассчитывает размер позиции от допустимого риска;
- в Demo/Live размещает post-only лимитный вход, биржевой Stop Loss и reduce-only лимитный Take Profit;
- отдельным watchdog каждые 2 секунды активирует защиту заполненного входа и аварийно закрывает позицию при пропаже SL/TP;
- блокирует новые входы, если последняя закрытая свеча устарела больше чем на два таймфрейма;
- показывает баланс, позиции, статистику и причины отсутствия сигнала в веб-панели;
- считает forward-метрики Demo и автоматически блокирует Live до прохождения всех критериев;
- атомарно сохраняет состояние, держит две ротационные копии и восстанавливается после повреждения JSON;
- переключает Paper, Demo и Live прямо в веб-панели без смешивания их статистики;
- может отправлять уведомления в Telegram.

`MT5Broker` подключён к тому же торговому контуру. Он вкладывает SL/TP прямо в
MT5-заявку, читает закрытые бары через `copy_rates_from_pos` и хранит MT5-состояние отдельно от Binance. Приложенный MT5 Demo-профиль
служит шаблоном: перед запуском `symbol_map` нужно подогнать под точные названия
криптосимволов выбранного брокера.

Команда `--check` для MT5 выполняет полный preflight без `order_send`: проверяет
подключение и разрешения терминала, Demo/Live-тип и разрешения счёта, каждое имя
символа, bid/ask, lot limits, поддержку market/limit/SL/TP, свежесть истории и
серверный `order_check`. Для market-заявок адаптер переводит битовые флаги
`SYMBOL_FILLING_MODE` в конкретный FOK/IOC/RETURN, вместо передачи флагов как типа заявки.

`--discover-mt5-symbols` читает каталог инструментов терминала через
`symbols_get`, предлагает `symbol_map` и не вызывает ни `order_check`, ни
`order_send`. Проверенный список Demo-брокеров и порядок подключения:
[`research/mt5_broker_shortlist_2026-08.md`](research/mt5_broker_shortlist_2026-08.md).

## GitHub CI

Workflow `.github/workflows/crypto-autobot-demo.yml` запускает тесты и публикует
статическую status-page. Он не читает Binance secrets, не сканирует рынок
по расписанию и не отправляет ордера.

Это намеренно: одноразовый GitHub runner не может постоянно следить за
заполнением лимитного входа и защитой SL/TP. Кроме того, проверка
3 августа 2026 показала Binance `HTTP 451` для IP GitHub-hosted runner. Для
Demo-торговли нужен непрерывный Mac или европейский VPS.

Локальная панель показывает номер последнего торгового цикла. Эндпоинт `/health`
возвращает `200` только при свежем heartbeat и, в Demo/Live, активном подключении
к брокеру; Docker также использует эту проверку для статуса контейнера. Значок
`State` показывает наличие резервных поколений. После автоматического восстановления
он указывает использованную копию, а повреждённый исходник остаётся рядом с state-файлом.

## Безопасный порядок

1. Paper: без ключей и без биржевых ордеров.
2. Binance Demo: виртуальные средства и настоящая механика API.
3. Live: только после проверки статистики и рисков.

Live-профиль имеет плечо 1x, резко уменьшенный риск и несколько независимых
блокировок. API-ключи читаются только из переменных окружения.

## Paper за одну минуту

```bash
cd "/Users/maksympiatachenko/Documents/Трейдинг"
python3 -m venv crypto_autobot/.venv
crypto_autobot/.venv/bin/python -m pip install -r crypto_autobot/requirements.txt
crypto_autobot/.venv/bin/python crypto_autobot/bot.py \
  --config crypto_autobot/config.paper.asymmetric-15m.example.json
```

Панель: `http://127.0.0.1:8090`

В панели `Paper` доступен сразу. Для `Demo` нужны Demo API-ключи в переменных
окружения. `Live` дополнительно заблокирован параметром `--allow-live-ui` и фразой
подтверждения. При открытой позиции смена режима запрещена.

Даже с этими параметрами Live останется недоступен, пока Binance Demo не накопит
минимум 30 активных дней сканирования и 100 закрытых сделок и не пройдёт автоматический gate:
`3.5-6.5` сделок/день, win rate не ниже `45%`, PF не ниже `1.10`, положительная
доходность, просадка не выше `10%`, номинальный RR не ниже `1:1.5` и нижняя
граница приблизительного 95% интервала expectancy выше нуля.

Активным считается только полностью завершённый день, за который бот получил не
менее 75% ожидаемых закрытых свечей. Для профиля из 10 пар на 15m это минимум
720 из 960 уникальных свечей. Текущий незавершённый день в счётчик не входит,
а его прогресс виден в разделе `Готовность к Live`.

Частота, win rate, PF, доходность и просадка считаются только по этим
подтверждённым дням. Дневные результаты хранятся отдельно от сокращённого журнала
панели, поэтому длительный Demo-тест не теряет старые сделки. Позиция, перенесённая
через полночь, целиком относится к дню её входа.

Раздел `Надёжность выборки` показывает Wilson-интервал для win rate,
приблизительный 95% интервал среднего PnL, payoff, break-even WR и средний результат
в `R`. Это защищает от перехода в Live по случайно удачной, но статистически слабой серии.

Один проход без постоянного запуска:

```bash
crypto_autobot/.venv/bin/python crypto_autobot/bot.py \
  --config crypto_autobot/config.paper.asymmetric-15m.example.json \
  --once
```

## Asymmetric 15m: текущий основной кандидат

Профиль торгует pullback по тренду в обе стороны на 10 USDT-парах. Вход ставится
post-only лимитной заявкой на откате `0.1 ATR`, Stop Loss равен `1.8 ATR`,
Take Profit `2.8 ATR`, номинальный RR `1:1.56`. Short-риск равен `0.15%` баланса,
а статистически более слабый Long получает только `0.025%`. Максимум 4 позиции,
12 входов в сутки и дневной стоп `1.2%`.

На 270-дневном validation: `4.72` сделки/день, win rate `45.60%`, `PF 1.179`;
при повышенных расходах `PF 1.106`. Подтверждающие следующие 60 дней дали `4.77`
сделки/день, win rate `50.35%`, `PF 1.237`; стресс `PF 1.156`. Точный RR `1:2`
проверялся, но не выбран из-за validation win rate ниже `45%` и более слабого PF.
Это исторический результат, а не гарантия будущей прибыли.

## Проверенный Demo-кандидат

В Binance Demo сигналы рассчитываются по публичным свечам Binance Production,
а баланс, стакан и ордера остаются в Binance Demo. Это разделение намеренное:
короткий параллельный аудит обнаружил заметное расхождение Demo-свечей с основным
рынком. Перед отправкой post-only вход дополнительно ограничивается текущими
Demo bid/ask, поэтому различие источников не превращает лимитную заявку в taker.
Панель отдельно показывает источник рыночных данных и среду исполнения.

При изменении рынка, набора пар, стратегии или риска бот меняет отпечаток
validation-профиля и начинает Demo-выборку заново. Баланс и общий журнал при этом
не стираются, но несовместимые дни и сделки больше не могут открыть Live gate.

Основной внутридневной профиль работает по закрытым 15-минутным свечам. Сигнал
создаёт post-only лимитную заявку на откате `0.1 ATR`; незаполненная заявка
отменяется после одной свечи. Заполнения и защитные ордера отдельно проверяются
каждые 2 секунды, без ожидания следующего полного сканирования десяти пар.

На macOS можно дважды нажать `start_asymmetric_demo.command`. Терминал попросит
Demo key и secret, скроет secret при вводе, проверит подключение без ордеров и
запустит панель. Ключи при этом не записываются в файлы.

```bash
caffeinate -i crypto_autobot/.venv/bin/python crypto_autobot/bot.py \
  --config crypto_autobot/config.demo.asymmetric-15m.example.json \
  --enable-orders
```

В панели появится блок `Проверка рыночного ордера`. Он позволяет открыть одну
маленькую Long или Short позицию на Binance Demo и сразу поставить Stop Loss и
Take Profit. Проверка заблокирована в Paper и Live. Сначала добавь виртуальные
USDT в кошелек Binance Futures Demo.

Для автоматического перезапуска на Mac дважды нажми
`install_macos_demo_service.command`. Скрипт сначала проверит Demo-подключение без
ордера, баланс, One-Way Mode, свежесть истории и все 10 инструментов, сохранит
ключи в macOS Keychain, затем установит пользовательский
`launchd`-сервис с рабочей копией в `~/Library/Application Support/CryptoAutobot`.
API-ключи не попадают в plist или файлы проекта. Это работает,
пока Mac включен, пользователь вошел в систему и крышка не закрыта. Launchd-Demo
слушает `http://127.0.0.1:8091`, поэтому может идти параллельно с Paper на `8090`.

Торговое состояние записывается атомарно и резервируется в `state_demo.json.bak1`
и `state_demo.json.bak2`. Копии обновляются при изменении позиции, баланса или
forward-статистики, но не при каждом двухсекундном heartbeat. Если основной JSON
повреждён, бот восстанавливает самую свежую валидную копию и сохраняет исходник как
`state_demo.json.corrupt-<время>`. Если валидной копии нет, бот не сбрасывает счёт
молча, а останавливается для ручной проверки.

Для постоянного VPS есть `compose.demo.yml`: контейнер автоматически
перезапускается, а `data/` подключен как постоянный каталог. Панель по умолчанию
слушает только `127.0.0.1:8090` хоста и открывается через SSH-туннель.

Полный воспроизводимый отчёт: [research/asymmetric_risk_audit.json](research/asymmetric_risk_audit.json).
Профиль остаётся кандидатом для Binance Demo, а не доказанной прибыльной системой
и не разрешением на Live.

Отчёт также считает все перекрывающиеся 30-дневные окна и детерминированный
10 000-path moving-block bootstrap. На данных до `2026-08-02` прибыльными были
`73.44%` обычных исторических окон и `66.39%` окон со стрессовыми расходами;
bootstrap дал `70.14%` и `62.18%`. Худший исторический стрессовый 30-дневный
результат был `-6.257%`, максимальная серия — 17 убыточных сделок. Это оценка
распределения риска, а не обещание доходности.

Короткий forward-аудит отдельно сравнивает одинаковую стратегию на свежих
Production и Binance Demo свечах. Он нужен для контроля частоты сигналов и
расхождения торговых сред, а не для подбора параметров по нескольким дням:

```bash
crypto_autobot/.venv/bin/python crypto_autobot/research/forward_frequency_audit.py --days 7
```

Последний снимок хранится в
[research/forward_frequency_latest.json](research/forward_frequency_latest.json).
Панель также показывает воронку исполнения: проверенные закрытые свечи,
выставленные лимитные заявки, заполнения, истечения и fill rate.

Панель показывает текущий прогресс в разделе `Готовность к Live`. Gate анализирует
только фактические forward-сделки Demo, а не исторический backtest. Если выборка
достаточна, но хотя бы одна метрика не прошла порог, Live остаётся заблокированным.

Кнопки `Test Long` и `Test Short` остаются рыночной проверкой подключения: они
нужны, чтобы вручную убедиться, что Binance Demo принимает вход и защитные ордера.

## Полная инструкция

Открой [ИНСТРУКЦИЯ_RU.md](ИНСТРУКЦИЯ_RU.md). Там есть:

- создание Binance Demo API;
- проверка подключения без ордеров;
- запуск Demo и Live;
- GitHub CI без API-ключей и отдельный запуск Binance Demo на Mac/VPS;
- исторический backtest с комиссиями и проскальзыванием;
- автоматический перезапуск через systemd;
- правила безопасности и частые ошибки.

## Проверка кода

```bash
python3 -m unittest discover -s crypto_autobot/tests -v
```

Бот не гарантирует прибыль. До Live оцени статистику на достаточном числе Demo-сделок,
максимальную просадку, комиссии и поведение во время нестабильного рынка.
